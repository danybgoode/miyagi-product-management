# Credentialed browser smoke — Sprint 1: wire the switch, count the skips, enumerate the secrets

**Status:** ⬜ not started

## Build contract (locked by the architect before the builder started)

Cite `README.md` D1–D4.

- **Verified 2026-07-26:** `browser-smoke.yml` passes 9 `MS_TEST_*` fixtures but **never sets
  `MS_TEST_BROWSER_AUTH`**. `e2e/_helpers/auth.ts`'s `authEnabled()` returns
  `process.env.MS_TEST_BROWSER_AUTH === '1'`, so every authed spec skips. 20+ specs reference the flag.
- **Clerk's testing token is rejected for production secret keys by design** — authed smokes work only
  against a **dev** instance (a preview). The workflow currently defaults to production. D1: the authed
  path targets the **preview**, with the protection-bypass token, as `ci.yml` already does. Read
  `ci.yml`'s preview-resolution + bypass handling and reuse that shape rather than inventing one.
- **Never convert a skip into a failure (D3).** Report loudly, fail nothing.
- **Secrets must never reach logs or artifacts.** Report counts and spec names only — never a fixture
  value. This is the MED-tier care point.
- Sign-in is **ticket-based** (`clerk.signIn({ page, emailAddress })`) — it needs only an email plus
  `CLERK_SECRET_KEY`, **no password**. The workflow's current `MS_TEST_*_PASSWORD` secrets are
  therefore likely vestigial; **verify against `auth.ts` and say so** rather than propagating them.

## Stories

### Story 1.1 — wire `MS_TEST_BROWSER_AUTH` against the preview ⬜
**As a** builder, **I want** authed browser smokes to actually run where they *can* run, **so that**
the credentialed layer stops being wired-but-dark.
**Acceptance:**
- The authed path targets the **preview** with the bypass token (D1), reusing `ci.yml`'s shape.
- `MS_TEST_BROWSER_AUTH=1` is set **only** on that path — the prod-targeted nightly must not set it
  (there it can only produce false confidence).
- The anonymous nightly against production is preserved unchanged — it works today and is real coverage.
- With no secrets provisioned, the job still **passes** (specs skip gracefully) — proven by a run.

### Story 1.2 — make the skip visible and countable ⬜
**As a** product owner, **I want** to see how much verification silently skipped, **so that** a green
tick stops meaning "nothing ran."
**Acceptance:**
- The job emits a summary: **N authed specs skipped, and which fixture each was missing** (name only,
  never a value).
- Written to the GitHub Actions **job summary** so it is visible without opening logs.
- The count is exposed in a machine-readable form the standup's evidence pack can consume, degrading
  cleanly when absent.
- **A run with zero fixtures provisioned produces a non-zero, accurate skip count** — this is the
  acceptance that matters, since it is today's real state. Paste it in the PR.

### Story 1.3 — the enumerated secret list, derived from the spec tree ⬜
**As** Daniel, **I want** an exact list of what to provision and what each unlocks, **so that** I can
close this in one sitting.
**Acceptance:**
- A committed list, **generated by scanning the spec tree** (D4) — not copied from the workflow's
  comment block, which has already drifted once (`MS_TEST_GALLERY_LISTING_ID` was a secret for a month
  before anyone wired it into the job env).
- Each entry: the env var, the spec(s) it unlocks, and what the fixture must satisfy (e.g. "a public
  listing with 2+ photos").
- **Explicitly resolves whether the `*_PASSWORD` secrets are still needed** given ticket-based
  sign-in. If they are vestigial, say so — provisioning ceremony nobody needs is its own cost.
- Any fixture the spec tree references but the workflow never passes is called out as a **live wiring
  gap**, the same class as the gallery precedent.
- `e2e/README.md` updated to match reality.

## Definition of Done (sprint)

- [ ] The anonymous nightly against prod still passes unchanged.
- [ ] The generated secret list committed and handed over.
- [ ] Verified no secret value appears in any log or artifact.
- [ ] Cross-agent review + fresh `pr-reviewer` (MED tier).
